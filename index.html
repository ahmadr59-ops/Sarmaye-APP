پشتیبان GitHub

راهنمای یک‌باره (حدود ۳ دقیقه)
  1. در github.com یک ریپوی Private با نام sarmaye-backup بسازید.
  2. Settings ← Developer settings ← Fine-grained tokens ← Generate new token.
  3. Repository access: Only select repositories ← sarmaye-backup.
  4. Permissions ← Repository ← Contents: Read and write. سپس Generate و توکن را کپی کنید.
  5. توکن را این‌جا وارد کنید. فقط روی همین گوشی ذخیره می‌شود.
اگر رمز بگذارید و فراموشش کنید، پشتیبان‌ها قابل بازیابی نیستند.

صندوق پیامک بانکی

پیامک بانکی

متن یک یا چند پیامک بانک را بچسبانید (بین پیامک‌ها یک خط خالی). هر پیامک به «صندوق پیامک» می‌رود و آنجا مثل پیامک‌های Shortcut بررسی می‌شود؛ پیامکِ تکراری دوباره ثبت نمی‌شود.

راهنمای ساخت Shortcut دریافت خودکار پیامک
  1. Shortcuts ← Automation ← + ← Message ← Message Contains: مانده ← Run Immediately.
  2. اکشن Text با چهار سطر: ###SMS / Current Date / Shortcut Input ← Sender / Shortcut Input ← Content.
  3. اکشن Append to Text File: فایل sarmaye-sms.txt در iCloud Drive ← Make New Line روشن.
  4. همین Automation را یک بار دیگر برای پیامک بانک شهر بسازید؛ کلمهٔ موجودي را از خود پیامک کپی کنید (با «ي» عربی نوشته شده و تطبیق iOS دقیق است).
  5. هر وقت خواستید: همین‌جا «دریافت پیامک‌ها از فایل» ← انتخاب sarmaye-sms.txt. پیامک‌های تکراری خودکار کنار گذاشته می‌شوند.
ارسال یک پیامک از Messages بدون کپی (Shortcut «ارسال به سرمایه»)
  1. Shortcuts ← + ← نام: ارسال به سرمایه ← از ⓘ پایین صفحه Show in Share Sheet را روشن و ورودی را Text کنید.
  2. اکشن Text با این سطرها: ###SMS · Current Date (ISO 8601) · دستی · Shortcut Input.
  3. اکشن Append to Text File ← همان فایل Shortcuts/sarmaye-sms.txt ← Make New Line روشن.
  4. در Messages متن پیامک را انتخاب کنید ← Share ← ارسال به سرمایه. دفعهٔ بعد «📥 دریافت از فایل» آن را هم می‌آورد.
دریافت کاملاً خودکار (بدون «دریافت از فایل»)
در هر دو اتوماسیون (مانده، موجودي)، بعد از Append to Text File این سه اکشن را اضافه کنید:
  1. Base64 Encode ← ورودی: همان Text ← Line Breaks: None
  2. Format Date ← Current Date ← Custom: yyyyMMdd-HHmmss-SSS
  3. Get Contents of URL ← https://api.github.com/repos/OWNER/REPOSITORY/contents/sms/ + Formatted Date + .txt ← Method: PUT ← Headers: Authorization = Bearer توکن ← Request Body: JSON: message = sms ، content = Base64 Encoded
OWNER و REPOSITORY باید مربوط به مخزن خودتان باشند؛ اگر اتصال GitHub تنظیم شده باشد، آدرس بالا از همان تنظیمات پر می‌شود. با بازشدن اپ و برقراری اتصال، پیامک‌های تازه بررسی می‌شوند.

تراکنش تکراری جدید

قفل ورود

این کد، ورود به رابط برنامه را محدود می‌کند؛ اطلاعات ذخیره‌شده روی دستگاه را رمزگذاری نمی‌کند.

با فعال کردن قفل، هر بار باز کردن برنامه یک کد عبور خواسته می‌شود. اگر کد را فراموش کنید، تنها راه بازیابی، پاک کردن کامل داده‌های برنامه است — پس حتماً پیش از فعال‌سازی یک پشتیبان (Backup) تهیه کنید.
قفل امنیتی فعال است

پشتیبان‌گیری

فایل شامل اطلاعات کامل حساب‌ها (شماره کارت، شبا) است. برای محافظت می‌توانید رمز عبور تعیین کنید — بدون آن نمی‌توان فایل را بازیابی کرد، پس آن را حتماً جایی امن یادداشت کنید.

پشتیبان‌گیری ابری

با یک حساب (ایمیل یا گوگل) وارد شوید تا بتوانید یک نسخه پشتیبان در فضای ابری Firebase خودتان ذخیره کنید — این نسخه فقط با همین حساب قابل دسترسی است.
پشتیبان Firebase دستی است. ورود یا بستن برنامه، نسخه ابری را تغییر نمی‌دهد. برای ذخیره نسخه این دستگاه، دکمه پشتیبان را بزنید.

بودجه ماهانه دسته‌ها

برای هر دسته سقف ماهانه (تومان) تعیین کنید. خالی = بدون سقف. با رسیدن به ۸۰٪ و ۱۰۰٪ هشدار می‌گیرید.

وام و اقساط

وام موردنظر را لمس کنید تا اقساط و جزئیاتش باز شود.

وام جدید

اگر تعداد کل و پرداخت‌شده را وارد کنید، باقی‌مانده می‌تواند خالی بماند و محاسبه می‌شود.

سررسید اولین قسط پرداخت‌نشده؛ حتی اگر مربوط به ماه‌های قبل است. تاریخ واقعی پرداخت را هنگام ثبت پرداخت وارد می‌کنید. فاصله اقساط ماهانه است.

تاریخ دریافت وام

اگر واریز قبلاً ثبت شده یا در موجودی شروع حساب لحاظ شده، «بدون واریز جدید» را انتخاب کنید. انتخاب حساب، مبلغ دریافت را یک بار به موجودی اضافه می‌کند؛ درآمد محسوب نمی‌شود.

اطلاعات تکمیلی (اختیاری)

این حالت برای پیگیری پرداخت‌هاست. مبلغ هر قسط شامل اصل و سود است؛ تفکیک آن‌ها حدس زده نمی‌شود. پرداخت از موجودی کم می‌شود و در گزارش، جدا از هزینه‌های دارای تفکیک نمایش داده می‌شود. مانده اصل و خالص دارایی تا مشخص‌شدن آن قابل محاسبه کامل نیست.

هر قسط دو بخش دارد: بازپرداخت اصل (کاهش بدهی — هزینه نیست و در سود و زیان نمی‌آید) و سود/کارمزد (هزینهٔ مالی و بخشی از هزینه‌های ماه).
اگر «واریز مبلغ وام به حساب» را انتخاب کنید، دریافت وام به‌صورت افزایش نقدینگی + ایجاد بدهی ثبت می‌شود و درآمد محسوب نمی‌شود.

پرداخت قسط

برداشت قبلاً در تراکنش‌ها ثبت شده است؟

انتخاب برداشت موجود، آن را به پرداخت قسط متصل می‌کند؛ موجودی دوباره کم نمی‌شود. هنگام حذف اتصال، برداشت اصلی برمی‌گردد.

تاریخ زیر، تاریخ واقعی پرداخت است؛ انتخاب ماه قبل، قسط انتخاب‌شده بالا را تغییر نمی‌دهد. اگر پرداخت قبلاً در مانده و موجودی شروع لحاظ شده، دوباره برداشت ثبت نکنید.

حواله ارزی (یورو ↔ تومان)

حواله جدید

سهم یورویی من در هر حواله = یوروی دریافتی − سهم همکار. این مبلغ پس از «تکمیل» حواله به انباشته اضافه می‌شود و در خالص دارایی شمرده نمی‌شود.

پرداخت حواله

این پرداخت از موجودی حساب کسر می‌شود ولی در «هزینهٔ ماه» و نمودارها نمی‌آید (تبدیل دارایی است، نه مصرف).

تمدید قرارداد

دوره قبلی با نرخ خودش در تاریخچه حفظ می‌شود؛ درصد وصولی هر سال با اجاره همان دوره محاسبه می‌گردد.

جزئیات تراکنش

اصلاح موجودی فعلی

اختلاف با تاریخ امروز در گردش حساب ثبت می‌شود؛ درآمد یا هزینه محسوب نمی‌شود. اگر تراکنشی ثبت نشده، ابتدا آن را ثبت کنید.
